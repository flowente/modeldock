# ModelDock

ModelDock turns a computer into a private AI server: a chat in the style of the frontier
assistants, running on local models through [Ollama](https://ollama.com), with its own accounts,
permissions and connection between devices. Nothing goes through a third-party service.

## What it does

- **Chat**: conversations with history and search, replies streamed word by word with a stop
  button, Markdown and copyable code, light and dark themes, phone layout.
- **Accounts**: the first administrator is created on the server computer; everyone else joins
  with a single-use invitation link. Roles: administrator, operator, viewer, member.
- **Model permissions**: each model is granted to groups or to single accounts. The server
  refuses requests to models that were not granted, and offers only models that can chat.
- **Devices** (`packages/link`): other computers and phones reach the server directly on the
  local network, over TLS with a certificate generated by the server.
  - *ModelDock Link client*: a device joins with an invitation (optional 6-digit code), waits
    for approval, then recognises the server by its certificate fingerprint.
  - *Browser on the same Wi-Fi*: opens `https://<server-ip>:4319`, accepts the certificate
    warning once, and signs in. Meant for phones until a phone app exists.
- **Settings**: account, appearance, models and permissions, users and groups, devices, and the
  server page (Ollama, memory, loaded models, checks, recent activity).

All data — accounts, conversations, permissions, audit log — lives in one SQLite file on the
server (`data/modeldock.db`). Passwords are stored as scrypt hashes; session and invitation
tokens only as SHA-256 hashes.

## Not there yet

- Access from outside the local network (IPv6, router port mapping).
- A phone app; phones use the browser on the same Wi-Fi meanwhile.
- A packaged ModelDock Link client: on a computer it runs from the command line for now.
- A one-file installer.

## Requirements

- Node.js 24 (development also tested with Node.js 22.23)
- pnpm 11
- Ollama (ModelDock can start it, and install it through winget or Homebrew when missing)

## Quick start

```bash
pnpm install
pnpm build
pnpm start
```

Open http://127.0.0.1:4317 **on the server computer** and create the administrator. The first
account can only be created there: from another device the setup is refused, so nobody on the
network can claim the server before its owner.

On Windows and macOS, `start-modeldock.bat` / `start-modeldock.command` do the same with a
double click and prepare their own Node runtime.

## Development

```bash
pnpm dev        # API on 4317 and Vite on 5173 (proxying /api)
pnpm test       # unit and integration tests (Vitest)
pnpm lint       # type-check every package
npx playwright test   # browser test against the built app (run pnpm build first)
```

## Configuration

Copy `.env.example` to `.env`. The main settings:

| Variable | Default | Meaning |
|---|---|---|
| `MODELDOCK_API_PORT` | `4317` | The API, which also serves the chat |
| `MODELDOCK_REQUIRE_LOGIN` | `true` | Every API call needs an account |
| `MODELDOCK_DATABASE_PATH` | `data/modeldock.db` | Accounts, conversations, permissions, audit log |
| `MODELDOCK_LINK` | `true` | The connection between devices |
| `MODELDOCK_LINK_PORT` | `4319` | Port other devices connect to |
| `MODELDOCK_LINK_ALLOW_BROWSERS` | `true` | Browsers on the same network may enter, behind the login |
| `MODELDOCK_OLLAMA_MODE` | `auto` | `fake` for demo data |

The API listens on `127.0.0.1` only. Other devices never reach it directly: they go through the
device connection on port 4319.

## Layout

```
apps/api            Fastify API; serves the built chat
apps/web            React chat and settings (Vite)
packages/core       shared types and rules
packages/auth       accounts, sessions, invitations, roles
packages/storage    SQLite database and stores
packages/link       connection between devices (server, client, invitations)
packages/ollama-adapter
packages/diagnostics
packages/testing    fakes for tests
```
